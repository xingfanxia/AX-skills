# 洁癖 — Knowledge Base Neat-Freak

让项目知识保持准确、容易查找、对接手者有用。做编辑，合并重复、修正过期信息，并保留仍有解释价值的决策和历史记录。

本 skill 是用户请求的知识整理工具。普通代码改动应同步它直接影响的文档；这不意味着每次收尾都要审查全部记忆、所有项目或全局配置。

## 范围和依据

先确定用户要检查或整理什么：指定文档、当前项目知识、个人记忆，还是跨项目交接。沿用当前对话已有的选择与授权，不重复确认。

- 只要求检查、评审或报告时，读取证据并返回发现，不修改文件。
- 要求整理或同步时，完成已授权范围内的修改；现有正确内容可以保持不动。
- 普通文档整理不授权写入个人记忆、提升全局偏好、清理其他项目或删除历史文件。
- 发现范围外的下游影响时，报告具体路径与影响；在多个项目都已纳入任务时，完成两边的对齐。
- 实质删除前核对精确目标、用途和引用关系，遵守当前删除授权与可恢复性要求。不要把“过期”或“已完成”本身视为删除依据。

用户明确要求更新记忆时，遵守当前环境的记忆来源、隐私和提升规则。项目事实不会自动成为跨项目偏好。

## 区分受众和职责

| 位置 | 受众 | 应保存的内容 |
|---|---|---|
| Agent 的实际记忆系统（若有） | 跨会话复用 | 已获授权维护的稳定事实或偏好，按该系统的提升规则处理 |
| 项目 `CLAUDE.md` / `AGENTS.md` | 项目里的 agent | 约定、边界和指向详细资料的路由 |
| `README.md` / `docs/` | 用户、同事和未来维护者 | 安装、接入、架构、操作与交接知识 |

同一个变化可能影响多个受众，但不必把全文重复写进每一层。维护一处权威说明，其他入口提供必要的摘要或链接。

平台路径线索见 [references/agent-paths.md](references/agent-paths.md)。先检查实际配置，不把参考路径视为所有环境都成立的事实。

## 盘点与核对

读取适用项目指令及任务涉及的资料，用 `rg --files` 列出范围内候选文件。明确指定整项目整理时，完整覆盖该项目的文档入口和被引用资料；局部修订只检查关联的文件和调用者。

根据当前代码、配置、用户决定或可核验来源判断内容，不只根据聊天摘要追加记录。保留一个轻量清单区分已检查、需修改和未解决；不为小改动创建额外台账。

常见关系可查 [references/sync-matrix.md](references/sync-matrix.md)：

- API、环境变量、数据结构改变时，查它们的接入和运维说明。
- 名称或路径变化时，查直接引用和导航入口。
- 跨项目协议变化时，核查已纳入范围的消费方。
- 记忆整理时，检查重复、事实冲突、索引与状态；历史事件不因完成而自动失去价值。

## 修改

更新现有权威说明，合并重复表达，修复失效链接。新建文档应服务明确的读者需要，不为了填齐模板而创建 architecture、runbook、handoff 或 CHANGELOG。

时间信息需要精确日期时，从证据推导日期；无法确定就标明不确定，不把“最近”机械改成猜测日期。引用、历史记录和用户原话不做无意义的关键词清零。

修改顺序按影响决定：通常先修影响使用者的说明，再修项目路由，最后处理已获授权的记忆更新。全局配置只在当前请求包含那项持久规则更新时修改。

对无法判定的矛盾，保留双方来源，提出具体待决问题。继续其他独立修改，不因一个分歧暂停全部整理。

## 验证与交付

核验修改的内容与证据一致，路径和链接有效，索引仍能找到目标，相关使用步骤与当前接口相符。只读命令可以验证可用性；不要为验证文档执行真实发送、部署、删除或付费操作。

按实际变更简要交付：修改了哪些文档或记忆、修正依据、验证结果，以及具体的未处理项。没有发现时如实报告，无需制造修改。

用户要求交接时，补充当前状态、下一步、未决问题和关键来源。默认在回复中提供；若用户要求交接文件，按其路径和现有项目约定保存，不套用别的平台 hook 或额外生命周期。
